# Glossary: IWR1843 Out-Of-Box (OOB) Radar Project

## IWR1843
TI single-chip 76–81 GHz FMCW radar sensor featuring an ARM Cortex-R4F (MSS), C674x DSP (DSS), Hardware Accelerator (HWA 1.0), and EDMA.

## MSS (Master Subsystem - Cortex-R4F)
The ARM Cortex-R4F core running TI-RTOS / SYS-BIOS, responsible for device initialization, RF BSS control via mmWaveLink, CLI command parsing on UART0 (`115200` baud), and assembling processed radar frame outputs into TLV packets on Data UART (`921600` baud).

## DSS (DSP Subsystem - TMS320C674x DSP)
The fixed and floating-point C674x DSP running at 600 MHz, responsible for 2D Doppler FFT, CFAR detection, 3D Angle of Arrival (AoA) estimation, Dense Elevation analysis, and NavPoint candidate generation.

## DPC / DPU (Data Path Chain / Data Path Unit)
The modular TI mmWave signal processing software architecture (`dpc/objectdetection`), where individual processing stages (RangeProc, DopplerProc, CFAR, AoA) are encapsulated as reusable units.

## TLV 1 (MMWDEMO_OUTPUT_MSG_DETECTED_POINTS)
Standard TI point cloud packet exporting detected objects in 3D Cartesian coordinates $(x, y, z, v)$ as single-precision floating-point values (16 bytes per point).

## TLV 7 (MMWDEMO_OUTPUT_MSG_DETECTED_POINTS_SIDE_INFO)
Standard point cloud metadata exporting SNR and noise floor estimates in units of 0.1 dB (4 bytes per point).

## TLV 20 (MMWDEMO_OUTPUT_MSG_NAVCANDIDATE_LIST)
Custom navigation obstacle stream generated by the Dense Elevation / NavPoint algorithm on DSS, containing obstacle physical width, range, elevation, and Doppler energy for UAV obstacle avoidance.

## Dense Elevation (`dense_elevation.c`)
DSS algorithm that performs fine-grained elevation angle search across range-azimuth bins using virtual antenna arrays to resolve low-lying or elevated obstacle profiles.

## NavPoint (`nav_point_gen.c`)
DSS candidate filtering and spatial clustering pipeline generating safe navigation waypoints and obstacle bounding vectors for UAV path planning.

## `guiMonitor`
The canonical TI mmWave CLI command gating individual TLV output streams (`guiMonitor <subFrameIdx> <detectedObjects> <logMagRange> <noiseProfile> <rangeAzimuthHeatMap> <rangeDopplerHeatMap> <statsInfo>`). Modified in `oob_1843` to gate TLV 20 via coherent HSRAM handshake without creating custom toggle commands.

## `navPointCfg`
CLI command configuring parameters for the NavPoint algorithm (elevation limits, azimuth limits, range limits, SNR threshold, and maximum output candidate count).

## L1 / L2 / L3 Memory Hierarchy
- **L1P / L1D SRAM**: 32 KB + 32 KB zero-wait-state memory for C674x instructions and scratchpad vectors.
- **L2 SRAM**: 256 KB DSS-local data RAM (`.l2data`).
- **L3 RAM**: 768 KB shared memory (`.l3ram`) holding the Radar Cube and detection matrices.

## Obstacle Bounding Box (ObstacleBox)
Spatial geometric representation of a detected obstacle cluster defined by 3D center position $(x, y, z)$, dimensions $(\text{width}_x, \text{depth}_y, \text{height}_z)$, radial velocity, and peak SNR.

## Two-Stage Detection Engine
Detection pipeline where Stage 1 runs hardware CASO-CFAR (Cell Averaging Smallest Of) on HWA to eliminate target masking, and Stage 2 runs software spatial clustering on C674x DSP to delineate contiguous range-azimuth energy into bounding boxes.

## Single Compact Bounding Box TLV
High-rate stream exporting solely bounding box descriptors and SNR over UART without transmitting raw point cloud lists, minimizing UART payload bytes and maximizing frame rate for downstream Raspberry Pi obstacle avoidance.
